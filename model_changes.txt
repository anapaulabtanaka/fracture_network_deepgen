2. utils/graph_utils.py
------------------------

Added new function get_spatial_bfs_sequence() (inserted after the existing
get_bfs_sequence()). This function performs a BFS starting from the
geometrically central node of the graph (closest node to the centroid of all
node positions) and sorts each BFS frontier by distance from the start node.
This reduces adjacency-matrix bandwidth compared to standard BFS, so the
RNN's lookback window captures more true spatial connectivity.

   def get_spatial_bfs_sequence(G, node_positions, start_id=None):
       - If start_id is None, selects the node closest to the centroid of all
         node positions as the BFS root.
       - At each BFS level, sorts the frontier nodes by their Euclidean
         distance from start_id before appending to the sequence.
       - Returns an integer array of node indices in spatially-ordered BFS
         order.

Updated extract_subgraph_from_bfs() to add a pos_attr parameter:
   - New signature:
       def extract_subgraph_from_bfs(G, n_nodes, start_id=0,
                                     randomize_nodes=True, seed=None,
                                     pos_attr=None)
   - When pos_attr is provided and the attribute exists on the graph, the
     function uses get_spatial_bfs_sequence() instead of get_bfs_sequence()
     to order the extracted subgraph's nodes.
   - Defaults to pos_attr=None, preserving existing behavior for all callers
     that do not opt in.

5. utils/general_utils.py
--------------------------

Added new function default_device():
   - Autoselects the best available PyTorch device.
   - Priority: MPS (Apple Silicon) > CUDA (NVIDIA GPU) > CPU.
   - Returns a torch.device object.

   def default_device():
       if torch.backends.mps.is_available():
           return torch.device('mps')
       elif torch.cuda.is_available():
           return torch.device('cuda')
       else:
           return torch.device('cpu')


6. gen_Tsanfleuron_2/graph_ddpm.py  (continued — DDIM numerical stability fix)
-------------------------------------------------------------------------------

Fixed catastrophic float32 cancellation in reconstruct() that caused the reverse
process to produce incorrect (corrupted) samples, explaining why the posterior
distribution did not match the prior (training data) distribution.

Root cause: the DDIM update computed an intermediate x0_pred by dividing by
sqrt(alpha_bar_t). Near t=T with the cosine schedule, alpha_bar_T ≈ 0, so
sqrt(alpha_bar_t) ≈ 1e-5 and x0_pred inflates to ~1e5. The following line then
multiplies by sqrt(alpha_bar_prev) ≈ 1e-5 to cancel, but in float32 (7 significant
digits) all precision is lost before the cancellation occurs.

Old (unstable) code:
    x0_pred = (G_batch.x - (1 - alpha_bar_t).sqrt() * eps_theta) / alpha_bar_t.sqrt()
    G_batch.x = (alpha_bar_prev.sqrt() * x0_pred
                 + (1 - alpha_bar_prev - sigma_t**2).sqrt() * eps_theta
                 + sigma_t * noise)

New (stable) code: eliminates x0_pred by algebraically expanding and simplifying.
All ratios remain O(1) throughout the entire timestep range:

    coef_x   = (alpha_bar_prev / alpha_bar_t).sqrt()
    coef_eps = ((1 - alpha_bar_prev - sigma_t**2).clamp(min=0.0).sqrt()
                - (alpha_bar_prev * (1 - alpha_bar_t) / alpha_bar_t).sqrt())
    G_batch.x = coef_x * G_batch.x + coef_eps * eps_theta + sigma_t * noise

The algebra:
    x_{t-1} = sqrt(ab_prev) * x0_pred + sqrt(1-ab_prev-s^2) * eps + s * noise
    Substituting x0_pred = (x_t - sqrt(1-ab_t)*eps) / sqrt(ab_t):
    x_{t-1} = sqrt(ab_prev/ab_t) * x_t
            + [sqrt(1-ab_prev-s^2) - sqrt(ab_prev*(1-ab_t)/ab_t)] * eps
            + s * noise

Numerical behavior:
  - ab_prev/ab_t = 1/alpha_t ≈ 1 (well-conditioned everywhere)
  - ab_prev*(1-ab_t)/ab_t = (1-ab_t)/alpha_t ≈ 1 near t=T, ≈ beta_1 near t=0
  - .clamp(min=0.0) prevents NaN from floating-point rounding making the
    argument of sqrt slightly negative (theoretically ≥ 0 for eta_ddim ≤ 1)

This fix makes no change to the mathematical meaning of the update — it is a
pure algebraic rearrangement. Results will differ numerically (because the
previous float32 precision loss is now avoided), which is the intended effect.


7. utils/graph_rnn.py  (GraphRNN edge density control)
-------------------------------------------------------

Added `threshold` parameter to generate_graph() and generate_graph_min_n_nodes()
to address the problem of generated graphs having too many edges (degree/variance
too large compared to training data).

Root cause: Bernoulli sampling with predicted probabilities always generates an
edge whenever p > 0 — even low-confidence predictions (~0.1-0.3) occasionally
fire, systematically inflating edge count across the many lookback positions in
the BFS window.

Fix: gate each Bernoulli draw so that edges are only sampled when the predicted
probability meets or exceeds a threshold. Below the threshold the probability
is zeroed, making that edge impossible.

   Old (always samples from full predicted probability):
       x_E = torch.lt(torch.rand(y_E_hat.size(), device=device), y_E_hat).to(torch.float)

   New (zeros out probabilities below threshold before sampling):
       x_E = torch.lt(torch.rand(y_E_hat.size(), device=device),
                      y_E_hat * (y_E_hat >= threshold).to(torch.float)).to(torch.float)

generate_graph() signature updated:
    def generate_graph(rnn_G, rnn_E, max_n_nodes, n_graph=1,
                       force_node1=True, return_encoded=False,
                       threshold=0.5, device=None)

generate_graph_min_n_nodes() signature updated:
    def generate_graph_min_n_nodes(rnn_G, rnn_E, min_n_nodes, max_n_nodes,
                                   n_graph=1, force_node1=True,
                                   return_encoded=False, threshold=0.5,
                                   device=None)
   threshold is forwarded to both internal generate_graph() calls.

Both functions also changed from device=torch.device('cpu') to device=None
with if device is None: device = default_device() resolution, consistent with
the same change made to graph_ddpm.py functions.

A module-level default_device() definition was added at the top of
graph_rnn.py (same standalone-fallback pattern as graph_ddpm.py).

Notebook call sites updated:
   - gen_Tsanfleuron_2/01_graphRNN_model_train.py: threshold=0.5 variable
     added before generate_graph() call, passed as argument
   - gen_Tsanfleuron_2/05_gen_graph.py: threshold=0.5 variable added before
     generate_graph_min_n_nodes() call, passed as argument

Usage: increase threshold above 0.5 (e.g. 0.6-0.8) to reduce edge density
when generated graphs have too many edges. Default 0.5 preserves prior behavior.


8. utils/graph_utils.py  (spatial BFS stochasticity)
-----------------------------------------------------

Added `n_start_candidates` parameter to get_spatial_bfs_sequence() to fix
the problem that spatial BFS was fully deterministic — always anchoring to
the single node closest to the geometric centroid, causing repeated calls
on the same graph to extract the same spatial patch.

Root cause: get_spatial_bfs_sequence() used np.argmin to pick one fixed
start node, so despite the random node permutation in extract_subgraph_from_bfs,
the BFS always started from the same physical region of G_main.

Fix: instead of always picking the single closest node to the centroid,
randomly select one from the n_start_candidates closest candidates.

   Old (fully deterministic):
       start_id = int(np.argmin(np.linalg.norm(pos - centroid, axis=1)))

   New (random choice from top-k candidates):
       dists_to_centroid = np.linalg.norm(pos - centroid, axis=1)
       k = min(n_start_candidates, len(dists_to_centroid))
       candidates = np.argpartition(dists_to_centroid, k - 1)[:k]
       start_id = int(np.random.choice(candidates))

get_spatial_bfs_sequence() signature updated:
    def get_spatial_bfs_sequence(G, node_positions, start_id=None,
                                 n_start_candidates=1)
   Default n_start_candidates=1 preserves prior deterministic behavior.

extract_subgraph_from_bfs() signature updated:
    def extract_subgraph_from_bfs(G, n_nodes, start_id=0,
                                  randomize_nodes=True, seed=None,
                                  pos_attr=None, n_start_candidates=1)
   n_start_candidates is forwarded to get_spatial_bfs_sequence() when
   pos_attr is provided.

Notebook call sites updated:
   - gen_Tsanfleuron_2/00_graphData_collection.py: both data set and test set
     calls updated to pass pos_attr='pos', n_start_candidates=10:
       G_list_data_set = [extract_subgraph_from_bfs(G_main, n,
                              pos_attr='pos', n_start_candidates=10)
                          for n in n_nodes]
       G_list_test_set = [extract_subgraph_from_bfs(G_main, n,
                              pos_attr='pos', n_start_candidates=10)
                          for n in n_nodes]

Usage: n_start_candidates=10 means the BFS start is randomly chosen from
the 10 nodes closest to the centroid, giving spatial variety while keeping
subgraphs near the geographic center of G_main. Increase for more spread.

11. utils/graph_rnn.py  (threshold revert)
------------------------------------------

Reverted all threshold-related changes from generate_graph() and
generate_graph_min_n_nodes() (originally section 7).

Reason: the threshold parameter interfered with the EOS (End Of Sequence)
mechanism. The model was trained with plain Bernoulli sampling; many of its
predictions sit between 0.1-0.5 ("possible but not certain"). Hard-zeroing
those made EOS fire unpredictably at any step, causing generated node counts
to vary wildly (e.g. 51 to 815 nodes) instead of matching the training
distribution. The correct fix is to retrain the model — at that point a
threshold can be reintroduced if edge density is still too high.

Changes reverted:
   - threshold=0.5 parameter removed from generate_graph() signature
   - threshold docstring entry removed from generate_graph()
   - Edge sampling restored to original Bernoulli form:
       x_E = torch.lt(torch.rand(y_E_hat.size(), device=device),
                      y_E_hat).to(torch.float)
   - threshold=0.5 parameter removed from generate_graph_min_n_nodes()
   - threshold=threshold forwarding removed from both internal
     generate_graph() calls in generate_graph_min_n_nodes()
   - threshold variable and argument removed from notebook call sites:
     01_graphRNN_model_train.py and 05_gen_graph.py

Note: device=None / default_device() changes from section 7 are kept.

Notes on backward compatibility
---------------------------------
All changes use default parameter values (pos_attr=None, eta_ddim=0.3,
device=None, n_start_candidates=1, patience=None) that preserve existing
behavior unless callers explicitly opt in. No existing training notebooks or
generation scripts are broken by these changes.

Callers that previously passed device=torch.device('cpu') explicitly will
continue to work unchanged. Callers that relied on the CPU default and do
not pass device will now automatically use the best available device.

To enable spatially-ordered BFS in training, callers should pass:
   - pos_attr='pos' to Graph_sequence_sampler_data_set (for topology-only RNN)
   - pos_attr='pos', n_start_candidates=10 to extract_subgraph_from_bfs
     (for data collection, to vary which spatial region is extracted)
The with_node_features dataset class applies spatial BFS automatically when
use_bfs=True, since positions are always available.
